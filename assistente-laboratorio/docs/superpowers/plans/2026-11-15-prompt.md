# Step 5, Prompt MCP e comandi `/prompts`, `/prompt` — Piano di implementazione

> **Per chi esegue:** SOTTO-SKILL OBBLIGATORIA: usare superpowers:executing-plans (esecuzione diretta) o superpowers:subagent-driven-development per eseguire il piano task per task. I passi usano le caselle (`- [ ]`) per il tracciamento.

**Obiettivo:** il server MCP pubblica i prompt `spiega(argomento, livello)` e `riassumi_conversazione(stile)`; la CLI offre `/prompts` (elenco) e `/prompt nome argomento=valore` (richiamo), controlla gli argomenti nell'host rispetto a `prompts/list` senza chiamare il modello, e manda i messaggi ottenuti al grafo come una domanda.

**Architettura:** prompt in `assistente/server_mcp.py` (`@mcp.prompt`) → nuovo modulo `assistente/prompt_mcp.py` con funzioni pure (lettura del comando con `shlex`, controllo degli argomenti, testo di `/prompts`) e nuovo errore `ErroreComandoPrompt(ErroreTurno)` → due funzioni sincrone in `assistente/collegamento_mcp.py` (elenco; richiamo con list → controllo → `prompts/get` nella stessa sessione) → `Conversazione.chiedi_messaggi(messaggi)` → in `terminale.py` una funzione di smistamento passata a `ciclo()` (che non cambia).

**Tecnologie:** Python 3.13, `fastmcp` 3.4.11, `mcp`, `langchain-mcp-adapters` 0.3.2 (`load_mcp_prompt`), `shlex` della libreria standard, pytest 9.1.1. Nessuna dipendenza nuova.

**Specifica:** `docs/superpowers/specs/2026-11-15-prompt-design.md` (commit `363ff0a` su `dev`, approvata). Chi esegue legge **entrambi** i documenti; le sezioni citate come §n sono della specifica.
